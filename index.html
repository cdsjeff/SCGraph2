Analysis command or request
Compact commands and natural language both work. Level, 1, 3 draws separate level lines in phases 1 and 3 and reports their median difference. Trend reports change per session, the slope difference, and the fitted separation between selected phases. IQRTrend, 1 fits Phase 1 and projects its trend and IQR through later phases. IQRs fitted to later phases stay local. T-U, series=Accuracy, 1, 3 compares phases 1 and 3 for Accuracy; series=2 chooses the second series within the selected Graph. The selectors above provide the same choices without typing. Parentheses in the data mark ghosted observations.
PND counts intervention scores that beat the best baseline score. NAP compares every baseline–intervention pair and gives each tie half credit. Changing the measure updates an active comparison.
CDC-NonPar reference
Conservative Dual Criteria Test, nonparametric version. The CDC-NonPar button under Level uses the A-phase median and raw IQR; the button under Trend uses the A-phase Theil–Sen projection and residual IQR. Choosing the other category’s button switches the same test to that reference. Pressing the active button turns it off. The selected IQR multiplier sets the improvement-side criterion. Changes refresh enabled comparisons automatically; shared settings stay synchronized in every test dropdown. The one-sided binomial test counts B points beyond that criterion; only the selected phases supply data. This choice does not change Tau-U.
Alpha
The threshold for the statistical comparison, usually 0.05. Tests use the selected improvement direction; Tau-U also offers a two-sided alternative.
IQR multiplier
Enter the proportion of A's IQR around the selected CDC reference (residual IQR for Trend, raw IQR for Level): The default is 0.20 (20%). Enter 0.50 for 50%, 1 for one IQR, or 0 for the selected reference alone. This multiplier applies only to CDC-NonPar; it does not change Tau-U statistics, rings, or cloud. Changes update enabled comparisons automatically. Shading begins in A and continues through the selected comparison phase: below the upper criterion for an increase, above the lower criterion for a decrease. PND uses the same direction rule with A's maximum/minimum. These are overlap/non-improvement regions; the binomial p-value tests the whole comparison phase.
Display
Classroom View uses plain-language explanations. Tau-U keeps ordinary observations plain and adds one extra ring to B points beyond the A reference in the improvement direction (median for uncorrected Tau-U, projected trend for corrected Tau-U) when visualization is On or Cloud only. For CDC-NonPar, it labels the improvement boundary and outlines B observations beyond it. Technical View shows Tau-U point symbols and more detailed explanations. Enabled comparisons update immediately when the view changes.
Baseline correction
Auto corrects when the baseline trend in the improvement direction has τ ≥ .20. Always applies the correction; Do not correct leaves the raw phase contrast. Both corrected and uncorrected comparisons can show a cloud; a nonzero correction adds a baseline-influence fade.
Statistical alternative
One-sided tests improvement in the selected direction. Two-sided tests either direction. Both use exact p-values: Mann–Whitney for the uncorrected comparison and Kendall S for the baseline-corrected comparison.
Visualization
Off keeps the data and A reference guide. On adds the cloud; Technical View also adds point symbols. Cloud only shows the cloud with the original data and criterion rings. Uncorrected Tau-U uses the A median; corrected Tau-U uses the projected A trend. Neither uses an IQR multiplier. Both show running Tau-U distinction shades, including when the applied correction is zero.

Starting SCGraph2

1. Enter the data

Enter one labeled series per line. Use | for phase changes and parentheses to ghost an observation without changing its session position.

Accuracy: 2,4,(5),3|7,8,9

2. Choose the graph layout in the data stream

  • Adjacent series lines overlay series in the same graph.
  • + on its own line creates vertically stacked multiple-baseline tiers on one shared Session timeline. Tiers may have different numbers of phases; SCGraph2 connects corresponding available phase-change lines by order (first-to-first, second-to-second, etc.). Extra phase lines remain unconnected.
  • - on its own line starts a new independent graph panel; up to three graphs are supported. Independent graphs may have different numbers of phases.
Student A: 2,3,3|6,7,8 + Student B: 2,2,3,4,4|6,7,8 - Accuracy: 40,45,50|70,78,85

3. View and format the graph

The graph updates automatically after you enter or paste data. The selected descriptive analysis or statistical test is recalculated when its series and phases are still available. In Graph Controls, choose the graph to edit. Each independent graph can have its own graph label, Y-axis label, vertical range, tick interval, and autoscale method.

Auto-scale is on by default for new graphs. Autoscale choices include the single-case rules for nonnegative/unbounded measures, known measurement bounds, measures allowing negative values, and the original SCGraph heuristic. Turn Auto-scale off for a manual Y range. The current effective scale is shown in Graph Controls.

4. Add goal lines when needed

Choose Graph → Goal Lines in the top menu to open the controls directly. Choose New goal line, then its series/tier, phase span, Y value, color and line type. Add up to three goals per series/tier, or use Edit beside a listed line. All added lines remain visible. Changes apply automatically; values, colors and styles are saved in project JSON.

5. Run an analysis

At the top of Analysis, choose Graph to analyze and then Series to analyze. Select reference phases for descriptive analyses or exactly two phases for statistical comparisons. Click the Level or Trend label for simple lines, or its caret to unfold all variants. Only one category list is open at a time; folding a list does not remove enabled analyses. Statistical tests have separate toggle buttons with adjacent settings dropdowns; shared settings synchronize and enabled tests refresh automatically. IQR Level and IQR Trend extend only Phase 1's reference line and IQR through later phases; later phases' lines and bands remain local. Tau-U offers Off (data and A reference guide), On (cloud and guide, with point symbols in Technical View), or Cloud only. The cloud uses ten blended shade levels with a smooth horizontal fade. Select the small caret beside Explanation in the Tau-U settings to expand the text. Classroom View keeps ordinary observations plain and rings B points beyond the selected A reference when visualization is On or Cloud only; Technical View includes the extra symbols and underlying quantities. The cloud darkness slider updates the graph immediately from Lighter to Darker, with a stronger dark-blue maximum. Analysis topic descriptions expand using the small caret beside each heading. These display choices do not change the statistics.

6. Choose a save location, then save or export

Use Project → Save Location to choose a folder when supported. Project → Load/Save and Report → Load/Save use the same complete project, including its report. Load recognizes project, graph, and supported data JSON. Report → Export Report prints/saves the report. Graph → Export Graph offers graph selection, full/compact layout, and SVG/PNG. Graph → Export Graph Data (JSON) saves an editable graph. Show Report / Hide Report is the first item in the Report menu.

X-axis controls: Open Graph Controls → X-Axis / Session Timeline for sequential/calendar spacing, minimum session span, first date and recurring weekdays. Click plotted dates to edit them. The displayed start number of each phase can be set independently below those controls.

7. Build a student report

Use Show Report in the header to lift the existing Report accordion into an overlay directly over the left panel; the button changes to Hide Report while the overlay is visible. The overlay is the same Report editor and toolbar—not a second copy—so edits, formatting, inserted graphs, tables, analysis results, and autosave are identical in both views. Report content is automatically saved locally as you work and is also included in SCGraph2 JSON state files. Use Save as PDF to open the browser print dialog and choose Save as PDF.

Tip: Set the analysis target with the darker Graph to analyze and Series to analyze selectors at the top of the Analysis panel. Analysis buttons show one selection at a time: choose a button to replace the visible analyses, or click the active button again to turn it off. Active buttons are highlighted. Data Input stays directly below the graph. Graph Controls and Analysis act as an accordion: selecting one fully collapses the other to its header. Each open body keeps its natural height, scrolling internally when needed; the next header follows directly below the content. Use Help → General Help for the full command and analysis reference.

Data entry

Enter one series per line using Label: values. Commas separate observations and a vertical bar creates a phase boundary. Session numbers continue across phases.

Sniffing: 2,4,5,2|6,7,4,5

Plain adjacent series lines are overlaid only when their phase lengths match exactly. If one series supplies explicit | boundaries and a companion series supplies none, SCGraph2 first infers those boundary locations for the companion series without inventing observations. If the resulting phase lengths differ, the series are automatically separated into independent graphs (up to three panels). Multiple-baseline tiers joined with + may still use different timing across tiers. Legacy label(...) directives are parsed as phase labels and G(...) goal directives are removed from the data stream.

Multiple graphs and multiple-baseline layouts

Use a separator on its own line between series. A minus sign (-) starts a new independent graph panel. SCGraph2 supports up to three graph panels, and each independent graph may have its own number of phases.

Accuracy: 2,3,4|7,8,9 - Rate: 10,11,12|15,17,18 - Errors: 8,7,6|3,2,1

Use a plus sign (+) to create a multiple-baseline group. Each joined series receives its own vertically stacked tier, but the tiers use one common horizontal Session timeline. Their phase changes may occur at different sessions, and the tiers do not need to contain the same number of phases.

Student A: 2,3,3|6,7,8 + Student B: 2,2,3,3,4|6,7,8 + Student C: 1,2,2,3,3,4,4|7,8,9

You can combine the syntax: - separates graph panels; + creates shared-timeline tiers inside a graph panel. Plain adjacent series inside the same tier are overlaid and therefore must use matching phase-boundary locations.

In a + multiple-baseline display, corresponding phase-change lines are connected across adjacent tiers. SCGraph2 connects corresponding phase-change lines by order across adjacent tiers (first-to-first, second-to-second, and so on). If one tier contains fewer phase lines than another, only the shared available lines are connected; any additional phase lines remain unconnected. Independent graph panels separated by - are not connected.

X-Axis / Session Timeline (v79): In Graph Controls, choose sequential spacing or proportional calendar time. Sequential mode offers Auto, 10, 15, 20, 25, 30, or a custom positive whole-number minimum span. A minimum adds room; it never removes observations. Existing projects without timeline settings retain 15-session sequential spacing. Compact export trims unused right-side space.

For calendar time, enter the first session date and select recurring weekdays. Session 1 uses that date exactly; later positions use the next selected weekday, including positions with missing data. Dates appear under session numbers and angle when space is tight. Click a date (or focus it and press Enter) to edit it. An edited date must remain between its neighbors. Changing the first date or recurring weekdays regenerates dates and clears edits. These timeline choices apply to every graph and tier; each graph retains its independent Y scale.

Displayed session numbering by phase: Set an optional positive whole-number start for each phase of the selected graph, or leave it blank to continue. Numbering follows the first series/tier of a shared graph. This changes labels only. Underlying session positions, missing/ghosted data, date chronology, phase boundaries and all statistical calculations remain unchanged. Project saves and graph JSON preserve timeline choices, edited dates and phase numbering.

Each multiple-baseline tier has its own horizontal axis line and Session tick marks so the common timeline is visible at every tier. Session numbers are printed only on the bottom tier.

Each graph panel created with - has its own display settings. In Graph Controls → Graph to edit, choose Graph 1, Graph 2, or Graph 3, then set that graph’s Graph label, Y-axis label, Y minimum, Y maximum, and optional Y tick interval. These settings do not change the other graph panels. Auto-scale may also be enabled independently for each graph. A + multiple-baseline structure is treated as one graph panel, so its stacked tiers share that graph’s Y-axis settings while retaining their own series/tier labels.

Auto-scale methods: Single-case — unbounded ≥ 0 starts at 0 and extends the upper axis to the next readable 1–2–5 major tick beyond the highest displayed data or goal value. Single-case — known bounds uses the full measurement range you enter in Known minimum/maximum. Single-case — allow negative values extends one readable major tick beyond both the lowest and highest displayed values. Original SCGraph heuristic preserves the earlier rule: start at 0 for nonnegative data (or pad below a negative minimum by about 5%) and add about 8% headroom above the maximum. Ghosted observations remain part of display scaling, and the single-case modes also include goal-line values so goals remain visible.

Analyzing one series when several are graphed

Analyses are always performed on one specified series at a time. The Graph to analyze and Series to analyze selectors are positioned at the top of the Analysis panel, above the analysis buttons. When multiple graph panels exist, choose the graph first and then the series/tier within that graph. A one-series graph auto-selects its series; a multiple-series or multiple-baseline graph asks you to choose the target series/tier.

Trend, series=2, 1
T-U, series=Accuracy, 1, 2

The selected Graph scopes series references, so series=2 means the second series/tier within the selected graph. A series may also be referenced by its exact label. Natural-language requests such as “perform Tau-U on series Accuracy, phases 1 and 2” use the currently selected graph as context.

Ghosting observations

Ghosting is encoded inside the data stream. Surround one numerical value with parentheses.

Sniffing: 2,4,(5),2|6,7,4,5

Here, Session 3 remains at Session 3 but is displayed in gray, omitted from active connecting lines, and excluded from visual and quantitative calculations. Parentheses do not consume or change session numbers. Remove the parentheses to restore the point. Data edits update the graph and selected analysis automatically.

Selected-phase analyses

The Phase(s) to analyze control selects the reference phases. Plain Level and Trend lines remain within each selected phase. IQR Level and IQR Trend fit each selected reference phase separately. Results show the numeric IQR (Q3 − Q1) in score units for each phase: from observed scores for Level, or from residuals around the fitted trend for Trend. Rerun an analysis to update its saved results. Only Phase 1's reference line and IQR band extend forward through all subsequent phases, including blank session positions. Later phases' reference lines and bands remain within their own phase. Other phases never enter a selected phase's median, trend fit or IQR calculation. PND / NAP, Mann–Whitney, CDC-NonPar, and Tau-U require exactly two phases, which may be nonadjacent.

Phase boundaries and graph conventions

  • Each | creates a vertical phase line halfway between the adjoining sessions. Phase boundaries can be styled individually as Standard, Thick, Double, or Dotted in Graph Controls; clicking a boundary on the graph cycles through those styles.
  • Observations are connected only within a phase; lines never cross a phase boundary.
  • Ghosted observations break the active connecting line rather than being bridged.
  • Phase names can be entered in the Data Input or Graph Controls module.

Goal lines

A goal line is a horizontal criterion line placed at a user-defined Y value. In Graph Controls → Graph → Goal Lines, choose the series or multiple-baseline tier, the start phase, the last phase the line should span, and the goal value. Set start and through phase to the same phase for a phase-specific goal, or choose a later through phase to extend one goal across multiple phases. Goal lines are graph settings rather than analysis overlays, so clearing or recomputing analyses does not remove them. Goal lines are included in saved JSON state files.

Goal, 1, 80
Goal, 1, 2, 80

The compact commands above place a goal at Y = 80 in Phase 1 only, or from Phase 1 through Phase 2, respectively, using the series/tier selected in Graph Controls.

Visual analysis

Level and Trend labels toggle their simple line analyses and unfold the options. Their adjacent carets only expand or collapse the option lists. Level contains IQR, PND / NAP, CDC-NonPar, Mann–Whitney, and Tau-U uncorrected. Trend contains IQR, CDC-NonPar, and Tau-U baseline corrected. PND, NAP and Mann–Whitney compare levels without fitting a baseline trend. Every analysis button toggles. Each statistical button has an adjacent settings caret. Graph, series and phase controls appear once at the top. Other shared controls are replicated in the relevant settings dropdowns and remain synchronized. Changes refresh all enabled comparisons automatically; opening a settings dropdown does not activate its test. Click an analysis button to replace the currently displayed analyses with that selection. Click the highlighted button again to turn it off. This applies across Level, Trend, IQR and all statistical test buttons; settings carets only open or close their controls.

Use the Analysis module or type commands such as:

Level, 1 IQRLevel, 1 Trend, 1 IQRTrend, 1 whiskerTrend, 1 whisker-Level, 1

Level uses the active phase median. When multiple phases are selected, results list each median and the signed difference (later phase minus earlier phase). Trend results list each Theil–Sen change per session, the signed slope difference, and the fitted score difference at the later phase’s first observed session, using the earlier trend projected to that same session. Comparisons follow chronological order between consecutive selected phases. These are descriptive differences, not significance tests. A trend comparison requires at least two active observations in each phase; a single observation is not reported as a flat trend. Missing and ghosted positions remain in session spacing, and calendar dates or displayed numbering do not change these rates. Trend uses a Theil–Sen estimator within the selected phase. IQR Level extends Phase 1's median and Q1/Q3 band through subsequent phases. IQRTrend extends only Phase 1's fitted trend and residual Q1/Q3 band through subsequent phases. Later phases' center lines and IQR bands stay within their own phase; all projections are clipped to the graph axes. Earlier saved IQR overlays retain their saved extents; rerun these analyses to apply the current Phase 1 projection rule. The separate CDC-NonPar comparison uses the selected Level or Trend reference ± the chosen IQR margin and performs the one-sided binomial test. IQR and whisker variants use active observations only.

IQR outlier legend and results (v79)

IQR Level and IQR Trend mark observations beyond the displayed reference’s outer fences with a small red dot at the data point. The legend shows the observation symbol with a red center and labels it Outlier. Switch the pane to Results for a count and a list of outlier sessions, values, observation phases and reference phases. The list is included in both simple and detailed results, exported Results panes and Insert → Analysis Results. If there are no outliers, Results says so. The fences are Q1 − 3 × IQR and Q3 + 3 × IQR, following the NIST description of Tukey outer fences. Fence quartiles use the same interpolated quartile method as the displayed IQR. IQR Level uses scores; IQR Trend applies the rule to residuals around the phase’s fitted trend.

Each visible IQR reference governs its own displayed span: Phase 1’s reference includes its projection into later phases; later-phase references stay local. A point is marked once if it crosses any visible reference’s outer fence. The hover description and results list identify the reference. Results use underlying session numbers; when displayed labels differ, both are given. Hiding the Phase 2 IQR also removes its flags from the list; flags from the Phase 1 projection remain. Missing and ghosted observations do not contribute to the fences or receive dots. Flags are descriptive, do not remove observations, and do not change statistical results. SVG/PNG exports and new report snapshots retain the dots.

Show graph title (v79)

Each graph keeps its own choice, including in project saves, graph JSON, SVG/PNG exports and new report snapshots. The overall figure title remains controlled by Global.

Rating scale labels (v79)

Open Graph Controls → Y-Axis → Rating scale labels, choose a graph, and enter score/label pairs in the two-column table. It starts with five rows and supports one to ten. The score field is three characters wide and the label field ten; longer entries are retained. For example, 5 | moderate labels the tick at numerical Y = 5 as “moderate.” A data value of 5 plots at that position regardless of the table row used. Blank labels keep normal numeric ticks; other ticks remain numeric. Labels apply to every tier of the chosen graph and update automatically. Adjust the Y limits above if a score is outside the visible range. Duplicate labeled scores and invalid values must be corrected before saving or exporting. Reducing the row count preserves the hidden entries but does not display them. Saved projects, graph JSON, SVG/PNG exports and new report snapshots retain the labels; statistics continue to use numeric scores.

Fraction scores (v79)

Enter fractions with a slash, for example Performance: 1/2,3/7,2/3|3/4,4/5,7/8. Fractions can be mixed with integers and decimals. Spaces around the slash and signed values such as -1/2 are accepted. Parentheses ghost the whole fraction, for example (3/7). Blank comma-delimited sessions still retain their positions.

Fractions are evaluated numerically for graphing and all analyses: 1/2 is 0.5, and 3/7 is approximately 0.428571. Axis labels, results and data tables use the existing decimal formatting. Project saves and graph JSON retain your original fractions. Hover over a fractional observation to see its original fraction and numeric value; ghosted observations are identified. These tooltips follow Graph Controls → Global → Show tooltips. A denominator of zero or an incomplete fraction keeps the last valid graph visible until corrected.

Automatic data updates (v79)

Entering or pasting data updates the graph after a short pause, whether or not an analysis is selected. Existing descriptive analyses and enabled statistical tests are refitted to valid data. Missing comma-delimited sessions and parenthesized ghost points retain their session positions. Invalid or incomplete entries keep the last valid graph and results visible with an error message; correct the entry to continue. Save, graph exports and new report insertions finish any pending data update before capturing it. The former Load & Graph Data and Un-ghost all points buttons have been removed. Restore an individual point by removing its parentheses or using the existing restore command.

Lines wrap to the available width and the pane grows to fit. The larger type is retained in full/compact SVG and PNG exports and newly inserted report graph snapshots. Analysis panes and attached controls (v79)

The Analysis header follows the bottom of the Graph Controls content, including its expanded subcontrols and panes. Short content does not stretch to the bottom of the viewport. Longer content scrolls inside a bounded body, with the next header immediately below that body. Opening Analysis rolls up Graph Controls; opening Graph Controls rolls up Analysis. Every active descriptive analysis or statistical test has one Legend / Results pane below the graph. Click the pane, or focus it and press Enter or Space, to switch faces. The face is remembered per analysis and saved with the project. Image exports and inserted graph snapshots retain the selected face as a static figure. The separate report Insert Results command continues to insert results text. Detailed results remain available from each analysis settings dropdown. IQR Level and IQR Trend include their numeric phase IQRs on the Results face.

Analysis buttons show one selection at a time: choosing a descriptive or statistical analysis clears the previous displayed analyses. Clicking the active selection turns it off. A CDC result counts B observations beyond its selected criterion, which can lie within the A-phase score range. Under the app’s one-sided binomial model (p₀ = .50), four of four crossing gives p = .0625, displayed as .063; five of five gives .03125.

CDC-NonPar also reports the four descriptive distinction categories from its criterion-crossing percentage: below 50% no difference, 50–<70% negligible, 70–<90% noticeable, and 90%+ distinct. These categories do not determine the p-value. A red ! appears on an analysis pane whenever a selected phase has fewer than five observed data points. Hover over it for the counts and an explanation of small-sample limitations. The explanation is also available in its accessible label. Missing and ghosted positions do not add observed points. Results retain the full written caution.

IQR comparisons report the later phase’s IQR divided by the earlier phase’s IQR, the percentage change, and the signed difference in score units. A ratio below 1 means a smaller later IQR; above 1 means a larger later IQR. IQR Level compares observed-score spread; IQR Trend compares residual spread around the fitted lines. Comparisons follow chronological order between consecutive selected phases, including nonadjacent selections. If the starting IQR is zero, the ratio and percentage change are unavailable and the result explains the absolute difference. These are descriptive spread comparisons, not added significance tests.

Analysis instructions and cloud darkness

Exact Mann–Whitney p-value (v79): Level → Tau-U uncorrected and Level → Mann–Whitney share the exact distribution for the between-phase sign count S_AB, equivalent to U = (nA × nB + S_AB)/2. The calculation reassigns pooled observations between phases of the observed sizes and retains tied scores. The two Level comparisons agree when using the same one-sided alternative and improvement direction.

Exact corrected Tau-U p-value (v79): Corrected Tau-U uses the exact distribution of adjusted Kendall S = S_AB − S_A, keeping each possible chronological order in A and ignoring order within B. One-sided p is the fraction of arrangements with S at least as large as observed in the selected direction. Two-sided p counts arrangements with absolute S at least as large as observed. These exact tests assume the scores can be exchanged across sessions under the null. They do not adjust for serial dependence or for choosing the contrast in Auto mode. Very large comparisons may exceed the in-app exact calculation limit; the p-value is then unavailable. Rerun the analysis to refresh results saved in an older version.

Every Analysis topic heading has a small caret that expands or collapses its description. Descriptions start collapsed; the selectors, command field, and other controls stay visible. The cloud darkness slider runs from Lighter to Darker; the far-left position hides it and the far-right position uses stronger dark-blue ink. It redraws immediately without rerunning the analysis or changing results. The setting is saved with the project and applies to graph exports. Older saved darkness settings are retained; projects without this setting use the default shade.

Tau-U level and trend references

Uncorrected Tau-U extends the active A-phase median as a gray dashed level guide. Baseline-corrected Tau-U fits a Theil–Sen trend to active A observations and projects it through later phases. Both extend to the displayed right edge, including blank sessions. Off keeps the data and guide; On adds the cloud and guide; Technical View also adds point symbols; Cloud only shows the cloud and criterion rings with the original data and hides the separate guide and technical contribution symbols. The uncorrected level reference needs at least one active A observation; the corrected trend reference needs two. No IQR multiplier is used by Tau-U or its visual criterion. It is a descriptive projection and does not change the test. The guide and cloud are clipped to the axes. Compact exports use their trimmed right edge. Older points-only/raw/corrected display settings load as On.

Select the small caret beside Explanation in the Tau-U settings to expand or collapse the explanation. It is collapsed by default and updates when the analysis or display changes. Classroom View uses plain language, keeps ordinary observations plain, and adds one outline to B points beyond the A median (uncorrected) or projected A trend (corrected) in the improvement direction when visualization is On or Cloud only. Cloud only retains these criterion rings and hides the separate guide and technical contribution symbols. The ring is a visual criterion flag, not an individual-point significance test. Technical View includes the extra point symbols, baseline τ, S_A, and correction quantities. The checkbox inside the explanation shows the combined Legend / Results pane below the live graph and includes its selected face in exports and report snapshots. It explains the dashed A reference guide, cloud distinction shades, and criterion ring; Technical View adds its contribution symbols. The pane stays outside the plotting area. Click it to switch between its symbol legend and calculated results. When visualization is Off, its default face is Results; the data/reference guide and statistics remain available.

The cloud has ten one-sided shade layers. All layers share the non-improvement side of the plot: the lower-score edge for an increase, or the upper-score edge for a decrease. Darkness stays strongest on that side and fades toward the A median for uncorrected Tau-U or the projected A trend for corrected Tau-U. These references also set the visual point rings, without an IQR multiplier. A-phase spread softens the display edge only; it does not set an inferential threshold. This is a custom directional visual reference, not a pointwise Tau-U overlap probability. In v79, cumulative Tau-U in the selected correction mode determines its descriptive darkness: below .50 is dark, .50–.69 medium-dark, .70–.89 light, and .90+ unshaded. An applied nonzero baseline correction adds a fade across B; uncorrected and zero-correction clouds use the running distinction categories without that fade. The lower two categories remain visible even when the applied correction is small; use the Lighter–Darker slider to adjust their relative darkness. Dense, smoothly interpolated horizontal gradient stops and a small blur soften the edges; the beginning and available right margin are feathered. Correction values at observed sessions are unchanged. This remains a descriptive influence field, not a probability distribution, confidence region, or significance band. Both corrected and uncorrected Tau-U show a cloud when visualization and ink are enabled. A running value of .90 or above remains unshaded by design.

Simple and detailed results

Results default to a short Comparison heading, a Note describing the observed result, and an Alert interpreting statistical evidence where available. Select Show detailed results in an analysis settings dropdown for formulas, counts, shading definitions, and the complete explanation. Switching text formats does not rerun the analysis or redraw the graph. The choice is saved in session JSON and Insert → Analysis Results uses the selected format. Rerun older saved analyses to generate concise summaries; their original detailed output remains available.

A labeled caution appears in both result formats and inserted reports when any analyzed phase has fewer than five observed data points. It identifies the affected phases and counts. Missing and ghosted sessions do not count toward five; unselected phases do not trigger the caution.

Hide p-values (v79): Check the box below the phase selector in Analysis to hide p-values and their significance conclusions in both Results formats, graph exports and new report inserts. Effect sizes and descriptive results remain visible. Uncheck to show the full results again. This choice is saved with the project; previously inserted report content stays as written.

Statistical comparisons default to one-sided tests in the selected improvement direction. Mann–Whitney compares raw score levels and ranks; CDC-NonPar uses the one-sided binomial test. Tau-U additionally offers a two-sided alternative. Tau results separate the raw phase contrast from any baseline correction: a raw Tau percentage is net pairwise non-overlap, not the percentage of individual points. The corrected Tau-U p-value is calculated separately from the uncorrected Mann–Whitney p-value. A nonsignificant test is described as a lack of clear statistical evidence; it does not prove no change or equivalence. PND, NAP and the practical distinction categories remain descriptive.

PND / NAP (v79): In Analysis → Level, open the settings arrow beside PND / NAP and choose a Non-overlap measure. PND is the default and uses the best Phase A score as its cutoff. NAP compares every active A score with every active B score, giving ties half credit. Its Results give the percentage and counts of favorable, tied and unfavorable pairs. There is no single cutoff or overlap shading. Use Mann–Whitney for the exact p-value. The selected measure is saved with the project.

PND shading: the shaded region begins at the start of the selected Phase A and continues through the end of the comparison phase, including blank sessions. It marks the overlap/non-improvement side of the Phase A criterion line: at or below the A maximum when higher scores are better, at or above the A minimum when lower scores are better. Ties do not count as non-overlap. PND is descriptive and has no p-value, so its shaded region is not a statistical significance region.

CDC-NonPar multiplier (v79): The default is 0.20, or 20% of Phase A’s IQR (residual IQR for Trend, raw IQR for Level). Enter any finite nonnegative proportion in the Analysis panel: 0.50 = 50%, 1 = one IQR, and 0 = the selected reference alone. Blank or invalid input is flagged. Changes update the criterion, point count, binomial result and shading automatically. A saved project keeps its chosen multiplier; projects without a saved multiplier use 0.20.

CDC-NonPar (Conservative Dual Criteria Test, nonparametric version) uses A observations only. Trend mode projects the Theil–Sen trend ± the selected proportion of residual IQR. Its Results show the fitted Phase A slope in score units per session, with the sign indicating rising or falling scores. Level mode projects the A median ± the selected proportion of raw IQR. Trend remains the default for older projects. Both modes retain the existing one-sided binomial counting method; the legacy commands TrendBinomial and binomial remain accepted and use the selected reference. For an increase, shading covers scores at or below the upper criterion; for a decrease, it covers scores at or above the lower criterion. This one-sided reference includes the opposite-direction region, starts in A, and continues through B. The selected center reference and both criteria remain visible. Shading is clipped to the plot and lies behind observations, phase lines, and goal lines. It is not a pointwise p-value or confidence region. The whole-phase one-sided binomial test counts B observations strictly beyond the improvement-side boundary, assuming p₀ = .50; showing shading in A does not add A observations to that test. Missing and ghosted positions add no statistical observations. Only the selected pair supplies test data, including for nonadjacent comparisons. Each statistical refresh reloads pending data edits, clears prior statistical layers, and rebuilds every enabled test. Enabled visual analyses remain available; edited data refit their selected phases. Older saved symmetric bands remain readable; rerun to generate the one-sided region. The legacy command binomial, 1, 2 remains accepted.

Classroom view applies to Tau-U and CDC-NonPar. For Tau-U it emphasizes the guide, simplifies explanations, and keeps ordinary points plain and rings B observations beyond the selected A reference; Technical View shows the underlying quantities and extra point symbols. For CDC-NonPar it adds a plain-language graph key, emphasizes the improvement-side criterion, and outlines B observations beyond it; Technical view keeps conventional lines. The CDC Level/Trend reference and shared display choice are saved with the session. Display changes update enabled comparisons automatically.

Save location, save state, and load state

Project → Save Location opens the browser folder chooser directly and can remember the chosen folder when SCGraph2 is opened as a top-level HTTPS page in a browser that supports the File System Access API (notably Chrome and Edge). Browser security prevents directory pickers inside cross-origin embedded previews/iframes and in some non-secure contexts. When folder selection is unavailable, Project → Save Location explains the available options, and saves/exports use browser downloads. A remembered folder can be changed or forgotten at any time and may occasionally require reauthorization.

Project → Save or Report → Save opens a filename dialog, then writes a versioned .json file to the remembered save folder when one is available; otherwise it sends the file to the browser's download location. The file contains the complete SCGraph2 session: the data stream (including +, -, phase boundaries, and parenthesized ghost points), per-graph labels, Y-axis labels, manual scales, tick intervals, autoscale methods and known bounds, goal lines, phase labels, selected analysis graph/series, analysis settings, overlays/results, commands, notes, and accordion open/closed state.

Project → Load or Report → Load is the single loading operation for saved SCGraph2 sessions, exported graph JSON, and other supported JSON data. Select a JSON file once; SCGraph2 detects its type. Saved sessions are restored with their settings, graph JSON is loaded as a graph, and other compatible files open the series-selection step. Candidate series are shown before anything is added to the graph; session numbers are preserved and null/missing values become blank session positions rather than zeros.
